v0.2.0 之后的第三个发布：**视觉路径**。控件树读不到时不再请用户「强行停止」目标 App，
改走截图 + 按图点击。

## 这一版新增

### 视觉路径（帧契约）

有些 App 对无障碍隐藏控件树（实测微信 8.0.78）。以前走到这一步只能停下来请用户处理；
现在改走截图：

- `capture_frame`：截屏并产出**一帧**（图 + 帧信息）。图缩到最长边 2048，
  1080×2344 的屏 → 943×2047。
- `tap_target` / `long_press_target`：按**该帧的图像像素**外框点击。

关键在于两套坐标系的换算被钉在一处（`ScreenFrame.toScreen`），
**模型侧只有「帧的图像像素」这一个坐标系**，永不换算、永不碰屏幕像素。
以前没有这层声明，模型按图给的坐标会系统性偏约 12.6%，**而且不报错**。

帧是**有状态的**：界面变了旧帧作废（`STALE_FRAME`），外框越界直接拒（`OUT_OF_FRAME`，
**故意不 clamp** —— 夹取会把「给错坐标」变成「点了个别的地方」）。动作后再截一张比对
8×8 指纹，只回 `changed` 布尔**不回图**（图会进历史并被每轮重发）；
`changed=false` 时 `ok` 仍是 true（`NO_VISIBLE_CHANGE`）—— 它是提示，不是失败。

工具面随之变化：新增 `capture_frame` / `tap_target` / `long_press_target`，
移除 `tap_point`（屏幕像素陷阱）与 `screenshot`（由 `capture_frame` 取代）。仍是 10 个工具。

### 变更

- **任务期不再自动开触摸探索**：它一开，注入的手势就被系统当探索事件吞掉，
  而树不可读时没有节点可走 `performAction` —— 等于「只能看不能点」，偏偏树不可读正是要走视觉的时候。
  它也救不了已经在跑的 App（那个状态是目标 App 进程启动时采样一次并缓存的）。
  机制与 debug 广播保留；**用户自己开着 TalkBack 时的语义兜底分支一个字没动**。
- 判「树不可读」从「节点数 < 2」改成「可见且有内容/可交互的节点一个都没有」——
  后者能抓住「节点不少、可读为零」的假阴性。
- `swipe` 的描述改成实情「约半屏」；触摸探索态下没有可滚动节点时不再谎报滑动成功。
- `image-offload` 启用：超请求图像预算时丢最老的图重试，而不是整轮失败（代价：**永久丢帧**，
  模型之后拿不到那张图）。

## 验证到什么程度

| 项 | 状态 |
|---|---|
| 坐标换算（`ScreenFrame.toScreen`） | ✅ JVM 单测钉住 |
| 「树不可读」判定 | ✅ JVM 单测（含「节点不少、可读为零」的假阴性用例） |
| 工具面 10 个（新 3 个 / 去 2 个） | ✅ 真机任务实测 |
| 任务期不再开触摸探索 | ✅ 真机实测 |
| **模型在图上估坐标准不准 / 动作是否真生效** | ⚠️ **尚未真机验证**（只有 PC 侧证据） |

也就是说：契约这一层是钉住的，**「模型能不能在图上找到目标」仍是能力问题，不是契约能保证的**。
验证步骤写在 `AGENTS.md` 的「真机」一节，验完把结论写回 `docs/android-accessibility.md` §9。

### 已知缺口

- **树不可读时无法输入文字**：`type_text` / `press(enter)` 都要控件树找输入框，
  视觉路径不解决输入 —— 「给某人发一条消息」这类任务仍做不到（自建 IME 见 `docs/roadmap.md` §2.5）。
- 用户自己开着 TalkBack 时全局触摸探索恒为真，注入手势一样被吞 —— 这条路只有语义动作可用。

## 安装

```bash
adb install -r tappet-v0.3.0-arm64-v8a.apk
sha256sum -c tappet-v0.3.0-arm64-v8a.apk.sha256   # 可选
apksigner verify --print-certs tappet-v0.3.0-arm64-v8a.apk
```

装完按应用内提示做两件事：**填自己的 LLM API key**（设置页）、**开启无障碍**
（真需要时应用会提示；只能由你手动开）。
