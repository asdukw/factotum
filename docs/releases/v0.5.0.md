# v0.5.0 —— 连接器（Gmail，只读）

v0.4.0 之后的第五个发布：**Tappet 有了第二条获取信息的通道**。

在此之前它只有一条路 —— 操作手机界面：信息从屏幕上来，动作回到屏幕上去，一切都经
`AccessibilityService`。这一版加了**连接器**：不经过无障碍，直接读用户云端账号里的数据。
首版是 Gmail，只读。

## 这一版新增

### 连接器（设置 → 连接器）

一个列表页，而不是散在设置里的几行 —— 因为连接器是**一类**能力。Gmail 可用，
Outlook 摆在旁边显示「即将推出」。加一个连接器 = 加一条数据 + 一个插件。

### Gmail 连接器

- **点「连接」→ 浏览器里点「同意」→ 自动跳回 App**。走的是 OAuth 2.0 授权码 + PKCE，
  回环重定向（`http://127.0.0.1:<随机端口>`）：不改 Manifest、不注册签名 SHA-1、不绑包名。
- **客户端 ID 与密码预置在包里**，新装用户不需要自己去 Google Cloud 注册应用。
  客户端密码不是机密（Google 原话：桌面应用是公共客户端、保不住秘密），真正的保护是 PKCE；
  但它必须发 —— 文档标「可选」而令牌端点实际会拒。想换用自己的应用注册，设置页里留了
  一行小字作为逃生门。
- **三个只读工具**：`mail_list`（列最近的邮件）、`mail_search`（Gmail 的 `q` 语法检索）、
  `mail_read`（读正文，4000 字符截断）。**没有任何写操作。**
- 邮件工具**不经过无障碍**：无障碍被关掉时设备工具全失效，邮件这条路照常可用。

### 凭据怎么放

- refresh token 进 Android Keystore 封装的 `SecretVault`：明文不落盘、不进日志、不进云备份。
  access token 只在内存（带过期缓存）。
- 插件**从不接触 refresh token**：它每次调用向本机的连接器桥要一个短命令牌
  （`{"action":"access_token","connector":"gmail"}`），桥只发令牌、不代理 Gmail 请求。
- 邮件正文只出现在给模型的工具结果里：不落日志、不落盘，**本机不保存邮箱副本**。
  所以「卸载后 Tappet 里还留着你的邮件」在结构上不可能发生。

### 授权面比能力面宽（这一版唯一的争议取舍）

申请的是 `gmail.modify`（读 + 写 + 发），而工具面**只有只读三个**。理由：Google 对已安装
应用不支持增量授权，扩权 = 所有已连接用户重走同意页，所以一次要齐。

代价写在 [docs/email-connector.md](../email-connector.md) §1.1：在只读 scope 下，
「插件被攻破也发不出邮件」这条边界是 **Google 兜的**；换成 `gmail.modify` 之后，
这条边界只剩**插件里那个唯一的只读出网函数**在守，从外部强制降级成自我约束。

## 已知限制

- **预置的 Google OAuth 客户端停在测试模式**：只有白名单里的测试账号能授权，且 refresh
  token 寿命受限（实测 7 天，到期需重连）。别人装这个包想用 Gmail，得换成自己的 OAuth
  客户端 ID 与密码。
- **授权过程要求 App 进程活着**（最长 10 分钟持有回环 socket）。进程被杀就得重来 ——
  正确做法是把等待回调放进前台服务，这一版没做。
- **Gmail 连接器只读**：没有发送 / 删除 / 归档 / 标记已读。写操作要等危险动作确认闸门
  （roadmap §3.2），闸门没做之前不开。
- 授权流程在真机上跑通过（一加 15T / ColorOS），但**只在一个账号上验过**。

## 验证

- `spotlessCheck` / `detekt` / `:app:lintDebug` / `:app:testDebugUnitTest` 全绿
- 插件 `npm test`：只读边界（断言所有出网请求都是 GET）、令牌不外泄、正文数据边界、
  HTML 降级、错误不回显响应体
- 真机：完整授权流程、令牌只落 SecretVault 密文、`mail_list` 真读到邮件、正文不进日志
