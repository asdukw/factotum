# v1.0.0 —— 改名 Factotum，手机上的 Linux 不再需要 Termux

这是 **1.0.0**：改名与包名更换是破坏性变更，按语义化版本直接升主版本。

这一版有两件大事：项目从 Tappet 改名为 **Factotum（执事）**，包名换成 `com.factotum.app`；
「让 agent 在手机上跑命令」从 Termux 桥改成**随 APK 内置的 proot + Debian**。

## 破坏性变更：新包名，旧安装不迁移

- `applicationId` 从 `com.tappet.app` 改为 `com.factotum.app`。设备上是一个全新 App：
  SQLCipher 数据库、Keystore 封装的口令、无障碍授权都不会跟过来，**需要重新安装并重新授权**。
- 存储身份同时全部换新：`factotum.db`、`factotum_app_keys` / `factotum-app-db-key-v1`、
  `SecretVault` 与 `AgentConfigStore` 的 prefs、连接器与提供商的 id、无障碍组件名。
- 公开下载目录从 `Download/Tappet/` 变为 `Download/Factotum/`。
- CI 的 secret 名改成 `FACTOTUM_*`（见 `docs/releasing.md`）。

## 新增：内置 Debian（proot），开箱即用的 `run_command`

以前要装 Termux、跑一次 `setup.sh`、点一次 `RUN_COMMAND` 授权，`run_command` 才会出现。
现在 APK 里带一份 `debian:bookworm-slim`（arm64）的 rootfs 和 Termux 分支的 proot：

- 装完就能用：首启解压 rootfs（实测 3262 个文件、0.7 秒），之后每条命令一次 proot；
- 完整的 Debian 用户空间：`apt`、PTY、Python、git、编译原生模块都可用；
- guest 里 HTTPS 直接用（CA 用 Android 自带的 145 张证书拼成 bundle）；
- 不再需要 Termux、不需要 root、不需要额外授权；卸载 Termux 不影响 Factotum。

实测（OnePlus 15T / Android 16）：`apt-get update` 9.3 MB / 12 秒，`apt-get install curl` 成功，
`curl https://deb.debian.org/` 返回 200，单条命令往返约 100 ms。

**边界**：每条命令是独立会话（`cd`、环境变量、后台进程都不保留）；没有 docker / systemd /
iptables（proot 不是真内核）；DNS 暂时写死公共解析器；没有常驻会话与端口转发。

## 新增：`run_command` 过审批

`run_command` 现在和日历 / 闹钟一样走 `tools/pre-execute → ask`：

- 默认每条命令弹一次确认面板；
- 审计日志只记「执行 shell 命令」，**不记命令原文**（原文只出现在确认面板上）；
- 「设置 → 执行层 → 写操作审批 = 全允许」后不再逐条打扰。

## 新增：定时任务用对话创建

「每天早上八点提醒我看天气」→ 模型拆出时间，直接落库并排 `AlarmManager`：

- `schedule_task` / `list_scheduled_tasks` / `update_scheduled_task` / `delete_scheduled_task`；
- 增 / 改 / 删都走审批；设置页不再有单独的定时任务入口。

## 变更

- APK 体积增加约 27 MB（内置 rootfs）。
- 文档：`docs/termux.md` 重写为 `docs/linux-on-phone.md`；AGENTS、README、全部引用同步改名。
- 修正一条错误结论：「Android 10+ 的 W^X 禁止执行可写目录」不成立 —— 实测 guest 二进制从
  `filesDir` 执行没有问题（启动器仍从 `nativeLibraryDir` 起）。

## 已知问题

- 重命名后需要重新配置 API key、连接器与无障碍授权（数据不迁移是这一版的选择）。
- 后台广播在 ColorOS 上会被推迟：App 不在前台时 `am broadcast` 返回成功但 receiver 不跑。
