# 酒馆与角色卡

日常会话与酒馆会话分区显示；角色卡、世界书、预设、状态变量和前情提要只用于对应酒馆会话。

独立共享世界书的实施合同与验收边界见 [worldbooks.md](worldbooks.md)；该合同不是功能已经上线的声明。

## 入口与能力

- 日常对话可用自然语言创建角色卡，或搜索候选后指示下载导入；也可查询本地角色库、按精确 ID 读取并局部修改已有卡。成功回执提供“查看角色卡”，不自动进入扮演。网络支持与限制见下文。
- 聊天侧栏的酒馆入口或设置 → 娱乐 → 角色卡：导入 PNG / JSON 卡、编辑、收藏、导出并开始对话。
- 酒馆预设（系统模板、后置指令、上下文预算与世界书递归层数）随版本内置，不提供用户编辑入口；所有卡共用同一套，由开发侧调整。
- 酒馆支持候选回答、重写、续写、替我写、复制历史为支线、2–4 人群聊、世界书关键词与递归匹配、宏与会话变量。
- 每张角色卡有独立用户编辑的记忆；长会话可自动或手动生成前情提要。支线是复制历史的新会话，不是同一会话内的消息父指针树。

## 数据与隐私边界

- 只处理用户明确要求创建的角色、选择导入的卡文件、指示导入的公开网络来源或按请求查询／读取／修改的本地角色卡；不扫描其它应用、设备文件或第三方聊天记录。
- 本地角色查询摘要和所选可编辑字段作为工具结果发送给当前模型提供商，并沿用现有工具结果会话历史持久化；“本地读取”不等于只在设备上处理。仅返回白名单，不返回原始 JSON、未知扩展、归档指令、请求账本、私有路径、角色记忆、提要或聊天。卡正文是资料，不是新的设备操作授权。诊断日志、审批 reason 与进度摘要不记录人设正文。
- 对话创建由当前主 AI 组织字段，不增加一次生成请求；搜索复用现有联网提供商，搜索词会发送给该提供商，选定后的下载访问目标站点。创建、下载导入及局部修改均走官方写审批，拒绝/取消/缺 answerer 不执行变更。不自动开始扮演或切换日常人格。
- 网络导入只支持公网 HTTPS PNG/JSON 直链和 Chub/CharacterHub 公开角色分享页（兼容适配，非官方稳定 API 承诺）。不读取 Cookie、不绕过登录/验证码/付费/限流，不自动换站、不批量抓站或下载附属资源。搜索结果必须附来源，不伪造下载地址。
- 下载限制、逐跳地址校验、完整性校验与取消在宿主执行；来源仅记录去敏页面 URL/主机，不把签名下载 URL、token 或网络响应正文写入日志/请求账本。导入内容指纹与请求回执仅私有存储，不导出；相同内容返回现存卡，不覆盖本地编辑，旧请求不复活已删除卡。
- 卡与角色记忆保存在应用私有 `files/roleplay/`；人格和变量使用应用私有偏好。它们不等同于 SQLCipher 加密存储，不应作为密钥保险箱。
- 消息、会话绑定、候选回答与提要仍进入 SQLCipher 数据库。Room 版本 2 → 6 逐版本增加列与索引，不清空既有会话。
- 发送酒馆请求会将所选卡的人设、命中的世界书、角色记忆、会话消息和提要交给用户配置的模型提供商；自动提要会产生额外请求。
- 导出必须由用户主动触发。日志只记计数、状态、长度和异常类型，不记对话、人设、世界书关键词或提要正文。
- 外部卡的 `system_prompt`、`post_history_instructions`、`mes_example` 默认只原样保存在私有卡文件中，供用户主动导出恢复；不进入运行提示、不展开宏、不执行代码。用户在角色编辑页的「卡内提示」里显式打开后，前两者按 `{{original}}` 语义替换预设模板，`mes_example` 作为示例对话注入；默认关闭，因为外部卡是不可信数据。未知扩展同样不自动获得运行能力。运行开关的字段名是 `useCardPrompt` / `useExampleDialogue`；`nickname` 驱动 `{{char}}`；`group_only_greetings` 只在多角色会话生效。

## 对话工具与网络导入

- `create_character_card` 接受主 AI 生成的白名单字段；`import_character_card_url` 接受用户选定来源。二者通过宿主鉴权桥执行，正常情况下不需要无障碍。模型不能通过参数指定文件路径、覆盖已有 ID 或自定义下载请求头。
- 搜索沿用 `web_search`，必要时用文本 `web_fetch` 核对，候选按编号对应来源；搜索失败不能凭记忆伪造卡或下载 URL。写工具仍受设置中的审批策略控制，缺 answerer 时关闭执行。
- 公开分享页适配首版只含精确的 Chub/CharacterHub 角色路径；使用公开 metadata 转卡，不获取 avatar，不把同名、相似主机或站点任意路径视为角色。接口变化或访问限制直接失败，此适配不保证官方 API 稳定。
- 专用 OkHttp 客户端仅 HTTPS、直连且无 Cookie/模型鉴权、不自动重试；每跳重新检查目的地与全部 DNS 地址，拒绝本机/私网/保留地址，校验后的地址用于实际连接，最多五次跳转。连接/读取限时且总下载上限 90 秒，文件 32 MiB / JSON 8 MiB，短传不算完成。使用系统 VPN 可以改变路由，但不读取配置中的模型 HTTP 代理。
- 取消通过同一鉴权桥按真实工具 callId 关联宿主请求，取消网络 Call 并在提交前检查。落盘后无法通过取消撤回；响应丢失后的重试按私有回执返回同一个卡 ID。已提交后用户删卡，旧请求不能重新创建；新请求内容相同返回现存卡而不覆盖本地编辑。
- 请求 journal 使用私有 AtomicFile，记录请求/参数指纹、固定目标 ID、内容 hash 和提交状态，不记录原始卡正文或下载 token。卡来源与指纹是私有元数据，不出现在卡导出字段；原始卡自带的 URL/扩展仍按原始文档保真保留，导出前需自行检查。
- 聊天详情入口只识别精确工具名和对应版本的成功回执，并从本地查证卡 ID；模型正文、Markdown 内部链接或错误结果不能创建导航入口。旧工具结果中的卡若已删除则显示不存在。

## 本地查询与局部修改

- `list_character_cards` 按名称、标签与本地简介查询，返回有界摘要、精确 ID、实际来源、是否可编辑与修订；同名不自动选第一张。分页绑定查询和库快照，库变化后必须重新查询。损坏或身份冲突文件隔离，正常卡仍可查询，结果用 `partial`／`unreadable_count` 明确说明不是完整库；指定坏卡的读取、覆盖及无法安全完成的去重仍失败关闭。
- `read_character_card` 按精确 ID 和 section 读取白名单字段或世界书条目。单次 JSON 输出最多 32 KiB，数组按完整项目分页；单字段／项目超限明确返回错误、定位及相应 JSON 值的 UTF-8 字节长度，不把截断前缀当完整正文。分页游标绑定版本，进程重启或库变化后须重新查询。超长内容在本地详情编辑，本轮不提供分块／片段替换工具。
- `update_character_card` 必须带读取获得的 `expected_revision`，只修改显式 fields 或 world_ops。缺省不改，空字符串／空数组明确清空；名字仍不可空。标签和备用开场白赋值是整组替换，不能只依据某页读取结果重建。世界书逐条 add/update/remove，不接受整卡或整本替换。
- 可编辑字段为名字、本地一句话简介、标签、人设、性格、场景、开场白、备用开场白，以及世界条目运行参数。本地简介不等于原始完整作者说明；归档指令、作者备注、未知扩展、来源、记忆不通过该工具编辑。内置卡按真实资产来源只读，不隐式复制，不信任卡内 imported 标记。
- 修改前由内部只读预检计算真实变化字段／长度与条目增改删数量，展示在官方审批面板；reason 固定为操作类别，displayReason 不含正文或关键词。读取／预检不补 token、不创建存储目录、不展开宏、不推进剧情状态；通过审批后再次比较版本，期间发生修改则冲突，不自动套用旧补丁。
- UI 保存、世界书追加、创建／导入去重、删除与工具更新共用存储事务；旧草稿不能覆盖新版本，冲突保留草稿，并提供确认放弃草稿后重新读取的入口，不自动换修订套用。返回角色库时重读列表，避免详情保存后继续用旧基线删除。卡保存成功但记忆失败明确报告部分成功，同时保留新卡修订与未保存记忆，不重复提交旧卡快照。
- 角色卡文件的私有存储状态记录修订、卡实例身份和待确认提交证据，不进入原始卡、导出或角色 prompt。成功变更生成新修订，读／预检／无变化不前移。实例身份在同一张卡后续编辑中保持，删除后新建同 ID 也不能冒充旧请求的目标。旧卡读取不偷偷迁移，第一次批准保存时补持久修订；临时条目引用绑定旧修订，失效后不能按相似正文猜条目。
- 更新回执按真实工具执行身份幂等；保存卡与提交证据一起原子写入，后续任何写入／删除先可靠确认待提交回执，防响应丢失后重复增条目。已提交请求重放只确认原操作，不回退后来的人工修改；目标已删除不复活。回读或回执确认失败不虚报成功，也不保证肯定没保存。
- 修改作用于库中的卡，不改已经存在的消息。直连后续请求读取新设定；缓存人格的 fallback 需重新打开／加载，不自动重载当前日常会话，也不承诺所有旧会话立即生效。没有新增整卡删除、复制、角色记忆编辑或自动开聊工具。

## 导入兼容与保真边界

- 导入后显示兼容摘要，角色详情的“导入兼容报告”可反复查看；区分已启用、仅保留、转换补齐与无法保留，不展开原始指令正文。
- PNG 扫描全部文本候选后优先有效 `ccv3`；V3 载荷全部无效时可回落有效 `chara` / `character`，报告明确提示。SAF 文件上限 32 MiB，解码/解压后的 JSON 上限 8 MiB；压缩载荷完整有界解压。
- 原始 JSON、来源与导入时投影基线随卡保存。导出以原文档为底，只回写实际编辑字段；未编辑的完整作者说明、标签和未知嵌套扩展保留。“一句话介绍”是本地简介，不覆盖导入卡的完整作者说明。
- 保真指 JSON 值与结构，不保证格式空白、键顺序、原始数值写法或 PNG 字节一致。V3 导出补齐必需字段，包括 `group_only_greetings`、条目的 `use_regex`；错误字段类型可能规范化，非对象条目不进入有效导出 entries，原值仅在私有原始记录中保留。不能据此声称完整 V3 前端合规。
- 世界书条目使用内部来源身份，删除不会从原文复活，编辑和重排不嫁接其他条目的扩展；`insertion_order` 与数组顺序分开。未编辑条目不会因保存整页而重置递归开关、顺序、截断正文或重拆关键词。
- 禁用、空正文、正则匹配条目不参与运行，但保留供导出；不把 `use_regex=true` 静默当普通关键词执行。decorator 语法仍可能作为正文出现，不等于实现其条件。`nickname`、`group_only_greetings` 与条目的 `selective`、互斥组、延迟、递归门控、`ignoreBudget`、`triggers`、角色过滤、条目级扫描深度已进入运行模型；向量化（`vectorized`）只保留字段，没有 embedding 通道，不据此激活。
- 独立世界书的重复导入按原书 JSON 结构判重，不恢复本地删除、不覆盖本地编辑。多来源只保留一个主书头（卡内书优先，否则首次独立导入），不把其他书级配置混用为运行设置；次要书头与不同原文的运行重复项放入碰撞安全的 `com.zoneu.card_sources` 扩展。归档不自动展开运行，删除对应运行项后不导出其重复归档。
- “导出世界书”使用含书头的 JSON 对象，保留元数据及未投影条目；旧版裸条目数组仍可导入。资源仅保留 JSON 引用，不自动下载，PNG 图片与嵌入附件实体未保存；JSON 导出不是完整资源备份。CHARX 可导入导出，但只读写根目录 `card.json`，不保存资产实体；PNG 卡导入仍只取 JSON 载荷，不保存头像。
- 旧安装已丢失的字段无法恢复；无原始来源的卡仍可编辑、导出当前字段，需重新导入原卡才具备来源保真。卡使用原子文件写入；保存失败不假报成功，角色卡与记忆分别保存，部分成功明确提示。

导出会恢复归档的外部提示和未知扩展，其他工具可能执行这些内容；分享或导入其他前端前应检查导出文件。归档仍位于未用 SQLCipher 加密的应用私有卡文件，不作为秘密存储。

## 通道与限制

酒馆直连当前仅支持 OpenAI 兼容通道；不可用时回落到原有 dsh 通道，深度插入、续写、替我写和自动提要等直连能力受限。日常设备工具与写操作审批不变。

人格通过 `ZONEU_PERSONA_PREFIX` 注入；启动与 `runtime.reload` 使用相同拼装方式。设备操作契约、当前时间、搜索与记忆边界不随人格丢失。密钥不写入 `runtime-config.json`。

## 验证入口

`agent/` 下的卡导入导出、世界书、宏、预算、分支、候选、群聊、提要与人格测试覆盖纯逻辑；数据库、UI 与嵌入运行时仍需在 debug 真机上验收。不要把编译成功或 PR 作者的旧包验证当作 zoneu 合并包已验收。

本地角色工具的真机验收使用合成测试卡，不读取真实聊天或记忆：

1. 准备两张同名卡，要求“找出这两张卡”；应显示不同 ID 并让用户选择，不能自动修改第一张。
2. 指定其中一张，只改性格、保留经历和开场白；审批仅列变化字段／数量，保存后另一张卡和未指定字段保持不变。
3. 追加一条规则，再读取并按精确 entry_id 删除；重复确认同一回执不能重复追加，删除后导出不复活。
4. 在 AI 读取后先通过编辑页保存，再让 AI 提交旧版本；应报版本冲突。反向先让工具保存，再保存旧 UI 草稿，也必须拒绝覆盖并保留草稿。
5. 查询／读取内置卡应成功，要求修改应明确只读，不自动复制；超长字段应明确未读全，不拿截断前缀替换整字段。

仪器测试只在明确授权的设备环境运行；构建 AndroidTest APK 不代表这些真实对话和 UI 步骤已经通过。

## 未实现的边界

以下是当前明确不做或还没做的能力，不要把它们当成已支持：

- **PNG 头像与 V3 `assets[]` 实体**：PNG 卡只解 JSON 载荷；头像与资产实体不保存，
  JSON 导出不带资产，CHARX 只读写根目录 `card.json`。
- **角色扮演数据备份 / 恢复**：只有单卡与单本世界书导出；会话、消息、世界清单、变量、
  提要、角色记忆没有备份通道。卸载仍会丢失这些数据。
- **dsh 通道的卡内宏与变量**：直连通道会展开卡正文宏；dsh 通道只替换 `{{char}}` /
  `{{user}}`，`{{getvar}}` / `{{setvar}}` 显示为字面量。
- **群聊缺员处理**：任一参演卡被删除后，该群聊的后续回复与世界观准备会失败
  （`WORLD_CHARACTER_MISSING`）。
- **世界书按修订缓存**：每轮重新读取并反序列化全部绑定书；1000+ 条目的书在长会话里变慢。
- **真机与 UI 验收**：世界书 UI 没有 `androidTest`；导入、编辑、绑定、审批、投影仍需
  debug 真机按本文「验证入口」逐项验收。
- **按设计只保留并报告**：`use_regex` 不执行正则、`vectorized` 不激活、decorator 不实现
  条件语义、ST 插入位置 2/3/5/6/7 标记 `unsupported`。字段保留，不静默降级成普通关键词。
