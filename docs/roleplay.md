# 酒馆与角色卡

日常会话与酒馆会话分区显示；角色卡、世界书、预设、状态变量和前情提要只用于对应酒馆会话。

## 入口与能力

- 聊天侧栏的酒馆入口或设置 → 娱乐 → 角色卡：导入 PNG / JSON 卡、编辑、收藏、导出并开始对话。
- 设置 → 娱乐 → 酒馆预设：配置系统模板、后置指令与上下文预算；可以按角色卡绑定。
- 酒馆支持候选回答、重写、续写、替我写、复制历史为支线、2–4 人群聊、世界书关键词与递归匹配、宏与会话变量。
- 每张角色卡有独立用户编辑的记忆；长会话可自动或手动生成前情提要。支线是复制历史的新会话，不是同一会话内的消息父指针树。

## 数据与隐私边界

- 只读取用户明确选择导入的卡文件；不扫描其它应用、设备文件或第三方聊天记录。
- 卡与角色记忆保存在应用私有 `files/roleplay/`；人格、预设和变量使用应用私有偏好。它们不等同于 SQLCipher 加密存储，不应作为密钥保险箱。
- 消息、会话绑定、候选回答与提要仍进入 SQLCipher 数据库。Room 版本 2 → 6 逐版本增加列与索引，不清空既有会话。
- 发送酒馆请求会将所选卡的人设、命中的世界书、角色记忆、会话消息和提要交给用户配置的模型提供商；自动提要会产生额外请求。
- 导出必须由用户主动触发。日志只记计数、状态、长度和异常类型，不记对话、人设、世界书关键词或提要正文。
- 外部卡的 `system_prompt`、`post_history_instructions`、`mes_example` 不导入。卡内容仍是外部数据；用户应只导入可信内容。

## 通道与限制

酒馆直连当前仅支持 OpenAI 兼容通道；不可用时回落到原有 dsh 通道，深度插入、续写、替我写和自动提要等直连能力受限。日常设备工具与写操作审批不变。

人格通过 `ZONEU_PERSONA_PREFIX` 注入；启动与 `runtime.reload` 使用相同拼装方式。设备操作契约、当前时间、搜索与记忆边界不随人格丢失。密钥不写入 `runtime-config.json`。

## 验证入口

`agent/` 下的卡导入导出、世界书、宏、预算、分支、候选、群聊、提要与人格测试覆盖纯逻辑；数据库、UI 与嵌入运行时仍需在 debug 真机上验收。不要把编译成功或 PR 作者的旧包验证当作 zoneu 合并包已验收。
